    What this service does

    A WhatsApp messaging gateway. Authenticated callers can send messages immediately or schedule them for future delivery — one-time or on a recurring schedule. The service queues, delivers, and retries automatically.

    Authentication

    Every send request must include a Bearer token in the Authorization header. Create tokens in the Tokens tab — one token per calling service is the recommended pattern.

    Authorization: Bearer <your-token>

    Phone number format

    The to field expects E.164 international format with no + sign and no separators — just the country code followed by the subscriber number. Drop any leading 0 from the local format before prepending the country code.

    CountryLocal formatSend as to
    Israel (+972)050-123-4567 / 0501234567972501234567
    USA (+1)(415) 555-012314155550123
    UK (+44)07911 123456447911123456
    Germany (+49)0151 123456784915112345678

    Common mistakes: a leading +, a leading 0 kept after adding country code, hyphens or spaces, or local-format-only digits without country code — all will fail.

    Note on first sends to a number: WhatsApp requires a one-time identity lookup (usync) for any number not yet seen by this account. If the recipient has never been messaged from this WhatsApp account before, the first send may time out — open a brief chat with them from the linked phone (so the contact syncs), then retry.

    Endpoints

    POST /api/send Send a WhatsApp message

    Queues a message for delivery. Returns immediately — delivery happens asynchronously with automatic retry.

    Request body (JSON)
    {
  "to":   "972501234567",   // phone number (international format, no +)
  "body": "Hello from the bot"
}
    Success response 202
    {
  "id":     42,          // message ID — use to track in the Messages tab
  "status": "queued"
}
    curl
    curl -X POST __HOST__/api/send \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"to":"972501234567","body":"Hello"}'
    Python
    import requests

r = requests.post(
    "__HOST__/api/send",
    headers={"Authorization": "Bearer <token>"},
    json={"to": "972501234567", "body": "Hello"},
)
print(r.json())  # {"id": 42, "status": "queued"}
    Node.js / fetch
    const res = await fetch("__HOST__/api/send", {
  method: "POST",
  headers: {
    "Authorization": "Bearer <token>",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ to: "972501234567", body: "Hello" }),
});
const { id, status } = await res.json();

    GET /api/events Server-Sent Events stream

    Subscribe to live connection and message status changes. Use this to avoid polling /api/status or /api/messages in hot loops.

    Events emitted
    event: status            // WA connection state changed
data: {"connected":true,"phone":"972501234567"}

event: connection_lost
data: {"at":1745666000000}

event: connection_restored
data: {"phone":"972501234567","at":1745666060000}

event: message_update    // delivery status changed
data: {"id":42,"status":"sent"}
    JavaScript
    const es = new EventSource("__HOST__/api/events");
es.addEventListener("connection_lost", () => console.warn("WA disconnected"));
es.addEventListener("message_update", (e) => {
  const { id, status } = JSON.parse(e.data);
  console.log(`message ${id} → ${status}`);
});

    Scheduled messages

    Schedule a message to send at a specific time — one-time or on a recurring schedule (daily, weekly, monthly, or any cron expression). Use the Schedule tab in the UI, or call the API directly.

    POST /api/schedule Schedule a message (text or media)

    Accepts multipart/form-data. Either body (text) or a media file field is required — both can be sent together.

    Fields
    to            required   Phone in E.164 format (no +) or WhatsApp JID
sendAt        required   Unix ms timestamp — must be in the future
body          optional*  Message text (* required if no media file)
recurrence    optional   daily | weekly | monthly | cron string (e.g. "0 9 * * 1")
                         Omit for a one-time send
media         optional*  File upload — image, video, audio, or document (* required if no body)
mediaCaption  optional   Caption to display with the media
toLabel       optional   Display name (stored for UI, not sent)
    curl — one-time text
    curl -X POST __HOST__/api/schedule \
  -H "Authorization: Bearer <token>" \
  -F "to=972501234567" \
  -F "body=Reminder: meeting in 1 hour" \
  -F "sendAt=1748005200000"
    curl — weekly image every Monday 9am
    curl -X POST __HOST__/api/schedule \
  -H "Authorization: Bearer <token>" \
  -F "to=972501234567" \
  -F "body=Weekly report attached" \
  -F "sendAt=1748005200000" \
  -F "recurrence=0 9 * * 1" \
  -F "media=@/path/to/report.pdf"
    Success response 201
    { "id": 7, "status": "scheduled" }
    Python
    import requests, time

r = requests.post(
    "__HOST__/api/schedule",
    headers={"Authorization": "Bearer <token>"},
    data={
        "to": "972501234567",
        "body": "Good morning!",
        "sendAt": str(int(time.time() + 3600) * 1000),  # 1 hour from now
        "recurrence": "daily",
    },
)
print(r.json())  # {"id": 7, "status": "scheduled"}

    PATCH /api/schedule/:id/disable Pause a scheduled message

    Moves status from scheduled → disabled. No sends will fire while disabled. Use /enable to resume.

    curl -X PATCH __HOST__/api/schedule/7/disable \
  -H "Authorization: Bearer <token>"
    PATCH /api/schedule/:id/enable Resume a disabled schedule 
    curl -X PATCH __HOST__/api/schedule/7/enable \
  -H "Authorization: Bearer <token>"
    DELETE /api/schedule/:id Delete a scheduled message

    Permanently deletes the schedule and any attached media file. Only allowed while status is scheduled or disabled — fired messages cannot be deleted.

    curl -X DELETE __HOST__/api/schedule/7 \
  -H "Authorization: Bearer <token>"
    GET /api/contacts/search Contact autocomplete

    Searches the local wacli DB for contacts and chats matching a name or phone number. Useful for resolving a display name to a JID before scheduling.

    Query params

    Response

    { "jid": "120363000000@g.us",           "name": "Team chat", "phone": "",             "kind": "group"   }
  ]

    Schedule lifecycle

    A scheduled message moves through these states:

    scheduled → fired one-time, after send
    scheduled → scheduled recurring — send_at advances to next occurrence
    scheduled ⇌ disabled pause / resume any time

    The scheduler checks every 60 seconds. Media files are stored in /data/scheduled-media/ and deleted automatically when a schedule is deleted.

    Message lifecycle

    Every message moves through these states:

    pending → sending → sent
    On failure: retried up to 3× with exponential backoff (30 s → 60 s → 120 s), then failed

    Messages queued while WhatsApp is disconnected will be delivered automatically once the connection is restored.

    Phone number format

    Pass the international number without a leading + and without spaces or dashes. wacli resolves the WhatsApp JID automatically.

    ✓  972501234567
✓  14155552671
✗  +972-50-123-4567
✗  050-123-4567
